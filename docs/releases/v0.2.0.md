# Docket 0.2.0

Docket 0.2.0 adds project-local, revisioned item types. Projects can define,
inspect, activate, evolve, and deprecate types without rebuilding Docket. Item
forms, lifecycle controls, queries, saved queries, moves, and MCP operations use
the definition revision pinned to each item.

Highlights:

- Project Types provides searchable type discovery, definition editing,
  revision history, lifecycle previews, and selected-item revision upgrades.
- Generated forms support text, numbers, booleans, enums, dates, timestamps,
  item references, lists, arrays, objects, defaults, constraints, explicit null,
  and unset values while preserving unknown future data read-only.
- Typed queries bind project, type, revision-aware fields, and derived lifecycle
  values. Same-named types in different projects keep independent identities.
- Type changes, item changes, lifecycle events, and audits use checked compound
  writes. Stale forms and incompatible lifecycle changes are refused rather than
  silently overwriting newer data.
- New `.dct` files use JSONL format 2.0 and a `.v2.cache` disposable SQLite
  cache. Exact type revisions can be transferred between compatible projects.

Existing JSONL 1.0 `.dct` files remain 1.0 when opened. Docket never upgrades
them automatically. Upgrade requires a preview, explicit confirmation that
incompatible writers are stopped, and an apply step that creates a backup.
Legacy SQLite files must first be promoted explicitly to JSONL.

Minerva's independent writer is incompatible with JSONL 2.0 type records and
must not open or write upgraded files. Older Docket executables also refuse the
new format. Use upgraded files only with compatible writers, and stop other
writers during upgrade or rollback.

Local verification before release ran 788 tests successfully. This is local
evidence; release CI and publication are tracked separately and are not claimed
here.
